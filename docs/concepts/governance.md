# Governance

**Launch status: Display Only.**

The full Knix concept includes community signaling or governance over protocol-level decisions.

## Potential scope

Governance may eventually cover proposals such as:

- adding or removing recognized pools;
- approving vault integrations;
- updating bounded risk parameters;
- changing protocol fee policy;
- ecosystem grants or incentives.

Critical safety controls should not be made weaker merely for governance convenience.

## Voting power

The governance model may use KNIX directly, staked KNIX, or a wrapped voting representation with snapshot-based voting power.

The exact model is intentionally undefined until the token design is finalized.

## Governance vs execution

A vote can be either:

1. **signaling** — expresses community preference but does not execute code; or
2. **executable governance** — successful proposals trigger or authorize onchain changes.

The DApp and docs must state which model is actually used.

## Launch display

The Vote page can show the governance concept and example proposal lifecycle, but no proposal should appear as active unless it is backed by real governance state.
